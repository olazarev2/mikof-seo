# Проверка исполнения

Скрипт обращается к живому `https://mikof.md` и по каждой из 22 задач ТЗ отвечает PASS / FAIL / WARN.
Он не спрашивает исполнителя и не читает его отчёты — только состояние боевого сайта.

## Запуск

```powershell
.\Verify-Seo.ps1              # полный прогон (с PageSpeed Insights, ~2 мин)
.\Verify-Seo.ps1 -Fast        # без PageSpeed, ~40 секунд
.\Verify-Seo.ps1 -Only A1,A5  # только указанные задачи
```

Без PowerShell — то же самое напрямую:

```bash
node verify/verify.mjs
node verify/verify.mjs --no-psi
node verify/verify.mjs --only A1,A5
```

Нужен Node.js 18 или новее — используется встроенный `fetch`. Никаких зависимостей ставить не надо.

Проверка B2 обращается к публичному API PageSpeed Insights, у которого жёсткая квота на анонимные запросы:
при частых прогонах он отвечает 429, и скрипт честно об этом пишет вместо того, чтобы показать ноль баллов.
Свой ключ (бесплатный, из Google Cloud Console) снимает ограничение:

```powershell
$env:PSI_KEY = "<ключ>"; .\Verify-Seo.ps1
```

## Что означают статусы

| Статус | Значение |
|---|---|
| **PASS** | задача выполнена, проверка на боевом сайте это подтверждает |
| **FAIL** | на сайте изменения не видно |
| **WARN** | проверка не смогла дать однозначный ответ (внешний сервис не ответил, элемент не найден) — смотреть глазами |

## Отчёты

Каждый прогон пишет `reports/ГГГГ-ММ-ДД.md`: таблица по задачам, детали по каждому провалу, список того,
что проверяется вручную. Отчёты коммитятся — накапливается история, по которой видно, что и когда появилось на сайте.

## Что скрипт не проверяет

- **B1** — Google Rich Results Test: открытого API нет, прогонять вручную на https://search.google.com/test/rich-results
- **D1** — цели GA4, подтверждение домена и отчёты Search Console: видны только в аккаунтах
- **C1** — полнота карты редиректов по всем 49 услугам: проверяются три образца
- **C4** — качество перелинковки по смыслу: считается только количество и наличие ключевых ссылок

## Пороги

Взяты из раздела «Критерии приёмки» ТЗ. Если порог нужно изменить, правится он в `verify.mjs` рядом с
соответствующей функцией `checkXX` — все они собраны в одном файле в порядке следования задач.
