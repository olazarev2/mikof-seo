Три дефекта, которые стоят трафика прямо сейчас

Остальные 19 находок важны, но эти три перекрывают эффект всего остального: пока они не закрыты, любая работа над контентом даёт долю результата.

1

Сайт существует в двух копиях

www.mikof.md отдаёт 200 OK без редиректа, а canonical на www-версии указывает сам на себя. Google индексирует именно www-копию — в выдаче www.mikof.md/en/service/35. Ссылочный вес делится пополам.

2

Прайс невидим для поиска

После полного рендера prices.shtml содержит 1144 символа текста, ноль таблиц и ноль упоминаний «lei». Цены грузит Livewire после выбора города. AI-краулеры JavaScript не исполняют — для них прайса не существует.

3

Ни одного <h1> и ни одного JSON-LD

На 83+ страницах отсутствует главный заголовок, вместо иерархии — подряд идущие <h2>, начиная с формы логина. Структурированных данных нет ни на одной из 117 проверенных страниц.

Блок A Технический фундамент

Приоритет P0. Оценка — 1–2 дня работы. Даёт основной эффект и является условием для блоков B и C.

A1

Склеить www и non-www

P0

Что сломано

https://www.mikof.md/ отдаёт 200 без редиректа, и canonical на этой версии ссылается сам на себя:

что сейчас отдаёт www.mikof.md
<link rel="canonical" href="https://www.mikof.md">
<link rel="alternate" hreflang="ru" href="https://www.mikof.md/ru">

Google уже проиндексировал www-копию: в выдаче присутствуют www.mikof.md/en, /en/contact.shtml, /en/service/35.

Что сделать

nginx
server {
    listen 80;
    listen 443 ssl http2;
    server_name www.mikof.md;
    return 301 https://mikof.md$request_uri;
}

server {
    listen 80;
    server_name mikof.md;
    return 301 https://mikof.md$request_uri;
}
  1. Зафиксировать APP_URL=https://mikof.md и строить canonical, hreflang и og:url только от него, а не от request()->getSchemeAndHttpHost() — сейчас разметка наследует хост запроса.
  2. Canonical — абсолютный, с языковым префиксом текущей страницы, единообразно со слэшем или без.

Как проверить

bash
curl -sI https://www.mikof.md/ | head -3
# ожидается: 301 → Location: https://mikof.md/

curl -s https://mikof.md/ru | grep -o '<link rel="canonical"[^>]*>'
# ожидается: href="https://mikof.md/ru"
A2

Вывести цены в HTML

P0

Что сломано

Самая коммерческая страница сайта после полного рендера в браузере содержит 1144 символа текста, 0 таблиц, 0 упоминаний «lei». В DOM — только заголовок «PREŢURI din 01.09.2026», пояснение и селектор «Alegeți clinica».

  • По запросам «preț operație cataractă Chișinău», «цена лазерной коррекции зрения Кишинёв» страница не ранжируется;
  • GPTBot, ClaudeBot, PerplexityBot, Google-Extended JavaScript не исполняют — прайса для них нет;
  • конкурент pro-med.md по тем же запросам показывает цену в сниппете.

Что сделать

  1. При первой загрузке рендерить на сервере прайс Кишинёва. Livewire оставить только для переключения городов.
  2. Каждый город — отдельный индексируемый URL: /preturi (canonical), /preturi/tiraspol, /preturi/ribnita. Селектор — обычные <a href>.
  3. Разметить семантической таблицей.
  4. Добавить блок «Ce include examinarea de 700 lei» — перечень обязательных и бесплатных исследований (сейчас спрятан в скобках прайса). Текст предоставляет заказчик.

  <tbody>
    <tr><td>Consultația medicului oftalmolog</td><td>700</td></tr>
  </tbody>
</table>

Как проверить

curl -s https://mikof.md/preturi | grep -c '<table'     # ≥ 1

A4

Починить hreflang

P0

Что сломано

Нет self-referencing и нет x-default. Google требует полный и взаимный набор — каждая версия перечисляет все, включая себя; иначе разметка игнорируется целиком.

сейчас на mikof.md/service/34
<link rel="alternate" hreflang="ru" href="https://mikof.md/ru/service/34">
<link rel="alternate" hreflang="en" href="https://mikof.md/en/service/34">
<!-- нет ссылки на саму себя (ro) и нет x-default -->

Что сделать

Выводить одинаковый блок из четырёх строк на всех трёх версиях:

html
<link rel="alternate" hreflang="ro" href="https://mikof.md/service/34">
<link rel="alternate" hreflang="ru" href="https://mikof.md/ru/service/34">
<link rel="alternate" hreflang="en" href="https://mikof.md/en/service/34">
<link rel="alternate" hreflang="x-default" href="https://mikof.md/service/34">

Заодно: на RU-версии отдаётся og:locale: ro_RO, а в og:locale:alternate стоит несуществующий локаль en_EN — правильно en_US.

Как проверить

bash
for u in https://mikof.md/service/34 https://mikof.md/ru/service/34 https://mikof.md/en/service/34; do
  echo "== $u"; curl -s "$u" | grep -o 'hreflang="[^"]*"' | sort;
done
# на каждом URL одинаковый набор: en, ro, ru, x-default
A5

Переписать sitemap и robots.txt

P0

Что сломано

  • 94 URL при примерно 320 реальных;
  • отсутствует главная страница;
  • отсутствует любой URL с /ru и /en — две трети сайта не заявлены;
  • нет services, prices, diagnostica, doctors, contact, clinic, reviews, question, gallery и всех 17 карточек врачей;
  • битый URL с двойной точкой Atentie_deosebita_fata_de_pacienti_minori..shtml → 404;
  • у всех записей changefreq: daily и priority: 0.8, включая статьи 2022 года;
  • пространство xmlns:xhtml объявлено, но hreflang в sitemap не передаётся;
  • в robots.txt нет директивы Sitemap: — там только User-agent: * и пустой Disallow:.

Что сделать

  1. Обходить все публичные маршруты во всех трёх локалях; целевой объём — не менее 300 URL.
  2. lastmod — из updated_at записи, а не из даты генерации.
  3. changefreq убрать; priority расставить осмысленно либо тоже убрать.
  4. Перед записью URL в sitemap проверять, что он отдаёт 200.
  5. Добавить hreflang-аннотации и отдельный sitemap-images.xml.
sitemap.xml
<url>
  <loc>https://mikof.md/service/34</loc>
  <lastmod>2026-08-24</lastmod>
  <xhtml:link rel="alternate" hreflang="ro" href="https://mikof.md/service/34"/>
  <xhtml:link rel="alternate" hreflang="ru" href="https://mikof.md/ru/service/34"/>
  <xhtml:link rel="alternate" hreflang="en" href="https://mikof.md/en/service/34"/>
  <xhtml:link rel="alternate" hreflang="x-default" href="https://mikof.md/service/34"/>
</url>
robots.txt
User-agent: *
Disallow: /cabinet
Disallow: /forgot
Disallow: /captcha
Disallow: /online-register/success
Allow: /

Sitemap: https://mikof.md/sitemap.xml
Sitemap: https://mikof.md/sitemap-images.xml

Не закрывать доступ GPTBot, ClaudeBot, PerplexityBot и Google-Extended: цитирование клиники в AI-ответах ценнее, чем защита текстов от копирования.

Как проверить

bash
curl -s https://mikof.md/sitemap.xml | grep -c '<loc>'   # ≥ 300

curl -s https://mikof.md/sitemap.xml | grep -o '<loc>[^<]*' | sed 's/<loc>//' \
  | while read u; do c=$(curl -s -o /dev/null -w '%{http_code}' "$u"); [ "$c" != 200 ] && echo "$c $u"; done
# ожидается пустой вывод
A6

Починить генератор meta description

P0

Что сломано

Двойное HTML-экранирование. В атрибут попадают уже экранированные сущности — в выдаче Google это выведется буквально:

что сейчас в разметке
/service/34
content="OCT, sau tomografia &amp;icirc;n coerență optică, este o investigație care&amp;nbsp;..."

/clinic.shtml
content="Centrul &amp;quot;Microchirurgia ochiului&amp;quot; din Chişinău a fost fondat &amp;icirc;..."

/ru/service/34
content="ОКТ, или оптическая когерентная томография, &amp;mdash; это современное..."

Румынская версия страдает сильнее всего: вся диакритика (î, ă, ș) хранится сущностями и превращается в мусор.

Слепая обрезка. Все описания режутся ровно на 255 символах и получают «…», хотя Google показывает 155–160.

Дубли и пустые. Из 117 страниц уникальных описаний 72. Одно и то же стоит на 31 странице, другое — на 12. Пустые: services.shtml, prices.shtml, diagnostica.shtml, все карточки врачей.

Что сделать

Порядок операций обязателен: декодирование сущностей → снятие тегов → нормализация пробелов → обрезка.

app/Support/Seo.php
public static function description(?string $manual, ?string $body, int $limit = 158): string
{
    if (filled($manual)) {
        return Str::squish($manual);
    }

    $text = html_entity_decode((string) $body, ENT_QUOTES | ENT_HTML5, 'UTF-8');
    $text = strip_tags($text);
    $text = Str::squish($text);          // NBSP и повторные пробелы

    return Str::limit($text, $limit, ''); // по границе слова, без многоточия
}

В админке добавить ручные поля meta_title и meta_description для каждой сущности во всех трёх локалях; автогенерация — только фолбэк.

Как проверить

В значении не должно быть подстроки &amp; и концевого ...; по всем URL из urls.txt уникальных описаний ≥ 90 %.

P3

Что сделать

Опечатки из A7 встречаются не только в title, но и в названиях услуг в меню, каталоге и на самих страницах — править в источнике (БД), а не в шаблоне. Отдельно проверить весь румынский контент на потерянную диакритику (urmarirea вместо urmărirea) и на кириллические гомоглифы внутри латинских слов — подтверждённый случай Hуpermetropie в EN-версии service/42.

Подтверждённый случай в шаблоне, а не в контенте. Фраза «Înregistrare online - pentru pacienții repetati» и соседняя «Cabinetul pacientului - pentru pacientii repetati» стоят в шапке и футере — то есть на всех ~320 страницах сайта:

Внутри одного словосочетания pacienții repetati первое слово набрано с диакритикой, второе — без. Это не разовая опечатка, а системный дефект шаблона.

Английские соответствия тех же элементов — обрывочный машинный перевод: «Cabinet office» (в английском это правительственный кабинет министров, а не личный кабинет пациента), «Online registration second», «Online registration first time». Вопрос к носителю языка: «pacienți repetați» выглядит калькой с русского «повторные пациенты». Румынский узус — скорее «pacienți în control» или «pacienți reveniți». Решение за редактором, но формулировка требует проверки.

Попутно: четыре из пяти таких «ссылок» — это <a href="#"> с модальным окном. Для поиска они не ссылки, и анкорный текст самого конверсионного элемента сайта пропадает впустую.

Заголовки кеширования в порядке: статика отдаётся с max-age=2592000, public, HTML — с no-cache, private. При TTFB 164 мс сервер узким местом не является.
