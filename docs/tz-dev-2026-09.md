## Блок A. Технический фундамент (P0)

### A1. Склеить `www` и non-www

**Что сломано.** `https://www.mikof.md/` отдаёт `200 OK` без редиректа. Более того, canonical на www-версии указывает сам на себя:

```html
<!-- то, что сейчас отдаёт https://www.mikof.md/ -->
<link rel="canonical" href="https://www.mikof.md">
<link rel="alternate" hreflang="ru" href="https://www.mikof.md/ru">
```

Google уже проиндексировал именно www-копию — в выдаче присутствуют `www.mikof.md/en`, `www.mikof.md/en/contact.shtml`, `www.mikof.md/en/service/35`. Весь сайт существует в двух полных копиях, ссылочный вес и поведенческие факторы делятся между ними.

**Что сделать.**

1. В nginx — 301 с www на голый домен и с http на https:

```nginx
server {
    listen 80;
    listen 443 ssl http2;
    server_name www.mikof.md;
    return 301 https://mikof.md$request_uri;
}

server {
    listen 80;
    server_name mikof.md;
    return 301 https://mikof.md$request_uri;
}
```

2. В Laravel зафиксировать `APP_URL=https://mikof.md` и строить canonical/hreflang/og:url **только** от него, а не от `request()->getSchemeAndHttpHost()`. Сейчас canonical явно наследует хост запроса — отсюда `https://www.mikof.md` в разметке.

3. Canonical должен быть абсолютным, с учётом языкового префикса текущей страницы и **со слэшем или без — единообразно**. Сейчас canonical главной `https://mikof.md` (без слэша), а сама страница доступна и как `/`, и как ``.

**Как проверить.**

```bash
curl -sI https://www.mikof.md/ | head -3          # ожидается: HTTP/1.1 301, Location: https://mikof.md/
curl -sI https://www.mikof.md/ru/service/35 | head -3
curl -s https://mikof.md/ru | grep -o '<link rel="canonical"[^>]*>'   # ожидается: href="https://mikof.md/ru"
```

**Что сломано.** `prices.shtml` — самая коммерческая страница сайта — после полного рендера в браузере содержит **1144 символа текста, 0 таблиц, 0 упоминаний «lei»**. 4. Добавить блок «Ce include examinarea de 700 lei» — перечень обязательных и бесплатных исследований (сейчас он спрятан в скобках прайса и пациентом не читается). Это отдельная контентная задача, текст предоставляется заказчиком.

### A4. Починить `hreflang`

**Что сломано.** Разметка неполная на всех трёх версиях. Сейчас:

```html
<!-- на https://mikof.md/service/34 (RO) -->
<link rel="alternate" hreflang="ru" href="https://mikof.md/ru/service/34">
<link rel="alternate" hreflang="en" href="https://mikof.md/en/service/34">
<!-- нет ссылки на саму себя (ro) и нет x-default -->
```

Google требует, чтобы набор был **полным и взаимным**: каждая версия перечисляет все версии, включая себя. Без self-referencing разметка игнорируется целиком.

**Что сделать.** На каждой из трёх версий выводить одинаковый блок из четырёх строк:

```html
<link rel="alternate" hreflang="ro" href="https://mikof.md/service/34">
<link rel="alternate" hreflang="ru" href="https://mikof.md/ru/service/34">
<link rel="alternate" hreflang="en" href="https://mikof.md/en/service/34">
<link rel="alternate" hreflang="x-default" href="https://mikof.md/service/34">
```

Плюс исправить `og:locale` — сейчас на RU-версии тоже отдаётся `og:locale: ro_RO`. И `og:locale:alternate` содержит `en_EN`, такого локаля не существует, правильно `en_US` или `en_GB`.

**Как проверить.**

```bash
for u in https://mikof.md/service/34 https://mikof.md/ru/service/34 https://mikof.md/en/service/34; do
  echo "== $u"; curl -s "$u" | grep -o 'hreflang="[^"]*"' | sort;
done
# на каждом URL ожидается одинаковый набор: en, ro, ru, x-default
```

### A5. Переписать sitemap и robots.txt

**Что сломано.**

- В `sitemap.xml` **94 URL** при примерно **320 реальных**.
- Отсутствует главная страница.
- Отсутствует **любой** URL с `/ru` и `/en` — то есть две трети сайта не заявлены вообще.
- Отсутствуют `services.shtml`, `prices.shtml`, `diagnostica.shtml`, `doctors.shtml`, `contact.shtml`, `clinic.shtml`, `reviews.shtml`, `question.shtml`, `gallery.shtml`, `ore-de-primire.shtml` и все 17 карточек `/doctor/{id}`.
- Есть битый URL: `https://mikof.md/Atentie_deosebita_fata_de_pacienti_minori..shtml` (двойная точка) → **404**.
- У всех 94 записей `<changefreq>daily</changefreq>` и `<priority>0.8</priority>` — сигнал бессмысленный, для статей 2022 года заведомо ложный.
- Пространство имён `xmlns:xhtml` объявлено, но не используется — hreflang в sitemap не передаётся.
- `robots.txt` не содержит директивы `Sitemap:`. Сейчас там только:

```
User-agent: *
Disallow:
```

**Что сделать.**

1. Генератор sitemap перевести на обход всех публичных маршрутов во всех трёх локалях. Целевой объём — не менее 300 URL.
2. `lastmod` брать из `updated_at` записи, а не из даты генерации.
3. `changefreq` убрать полностью (Google его игнорирует) либо задать реалистично: `weekly` для прайса и главной, `yearly` для статей.
4. `priority` убрать или расставить осмысленно: 1.0 — главная, 0.9 — прайс и услуги-локомотивы, 0.5 — статьи.
5. Добавить hreflang-аннотации внутрь sitemap:

```xml
<url>
  <loc>https://mikof.md/service/34</loc>
  <lastmod>2026-08-24</lastmod>
  <xhtml:link rel="alternate" hreflang="ro" href="https://mikof.md/service/34"/>
  <xhtml:link rel="alternate" hreflang="ru" href="https://mikof.md/ru/service/34"/>
  <xhtml:link rel="alternate" hreflang="en" href="https://mikof.md/en/service/34"/>
  <xhtml:link rel="alternate" hreflang="x-default" href="https://mikof.md/service/34"/>
</url>
```

6. Убрать битый URL и добавить в генератор проверку: перед записью в sitemap URL должен отдавать 200.
7. Отдельный `sitemap-images.xml` для медиа `/storage/media/`.
8. `robots.txt` привести к виду:

```
User-agent: *
Disallow: /cabinet
Disallow: /forgot
Disallow: /captcha
Disallow: /online-register/success
Allow: /

Sitemap: https://mikof.md/sitemap.xml
Sitemap: https://mikof.md/sitemap-images.xml
```

Доступ GPTBot / ClaudeBot / PerplexityBot / Google-Extended **не закрывать** — цитирование в AI-ответах для клиники ценнее, чем защита текстов.

**Как проверить.**

```bash
curl -s https://mikof.md/sitemap.xml | grep -c '<loc>'        # ожидается: >= 300
curl -s https://mikof.md/sitemap.xml | grep -o '<loc>[^<]*' | sed 's/<loc>//' \
  | while read u; do c=$(curl -s -o /dev/null -w '%{http_code}' "$u"); [ "$c" != 200 ] && echo "$c $u"; done
# ожидается: пустой вывод
curl -s https://mikof.md/robots.txt | grep -i sitemap
```

### A6. Починить генератор meta description

**Что сломано.** Три независимых дефекта.

**1. Двойное HTML-экранирование.** В атрибут попадают сущности, уже прошедшие экранирование:

```html
<!-- /service/34 -->
<meta name="description" content="OCT, sau tomografia &amp;icirc;n coerență optică, este o investigație modernă care&amp;nbsp;vizualizează...">
<!-- /clinic.shtml -->
<meta name="description" content="Centrul &amp;quot;Microchirurgia ochiului&amp;quot; din Chişinău a fost fondat &amp;icirc;...">
<!-- /ru/service/34 -->
<meta name="description" content="ОКТ, или оптическая когерентная томография, &amp;mdash; это современное обследование...">
```

В выдаче Google это выведется буквально: `tomografia &icirc;n coerență`. Румынская версия страдает сильнее всего — вся диакритика (`î`, `ă`, `ș`) хранится в виде сущностей и превращается в мусор.

Причина: текст из редактора хранится с HTML-сущностями, дальше применяется `e()` / `{{ }}`, который экранирует `&` повторно. Нужен `html_entity_decode()` **до** экранирования.

**2. Слепая обрезка.** Все описания обрезаются ровно на 255 символах и получают `...`. Google показывает 155–160 символов, остальное отбрасывает; обрезка посреди слова выглядит как ошибка.

**3. Дубли и пустые.** Из 117 проверенных страниц уникальных описаний — 72. Одно и то же описание стоит на **31** странице, другое — на **12**. Пустые описания: `services.shtml`, `prices.shtml`, `diagnostica.shtml`, `doctor/1` и остальные карточки врачей.

**Что сделать.**

```php
// app/Support/Seo.php
public static function description(?string $manual, ?string $body, int $limit = 158): string
{
    if (filled($manual)) {
        return Str::squish($manual);
    }

    $text = html_entity_decode((string) $body, ENT_QUOTES | ENT_HTML5, 'UTF-8');
    $text = strip_tags($text);
    $text = Str::squish($text);                    // NBSP и повторные пробелы

    return Str::limit($text, $limit, '');          // обрезка по границе, без многоточия
}
```

Порядок операций обязателен: `html_entity_decode` → `strip_tags` → нормализация пробелов → обрезка.

В админке добавить ручные поля `meta_title` и `meta_description` для каждой сущности во всех трёх локалях; автогенерация — только фолбэк.

**Как проверить.**

```bash
curl -s https://mikof.md/service/34 | grep -o '<meta name="description"[^>]*>'
# в значении не должно быть подстрок "&amp;" и не должно быть "..." на конце
```

Плюс скрипт: собрать description со всех URL из `urls.txt`, посчитать дубли — уникальных должно быть не менее 90 %.

### D3. Орфография и диакритика в контенте

Опечатки из A7 встречаются не только в title, но и в названиях услуг в меню, каталоге и на самих страницах — править в источнике (БД), а не в шаблоне. Отдельно проверить весь RO-контент на потерянную диакритику (`urmarirea` вместо `urmărirea`) и на кириллические гомоглифы внутри латинских слов (подтверждённый случай: `Hуpermetropie` в EN-версии `service/42`).

**Подтверждённый случай в шаблоне (не в контенте).** Фраза «Înregistrare online - pentru pacienții repetati» и соседняя «Cabinetul pacientului - pentru pacientii repetati» стоят в шапке и футере, то есть на всех ~320 страницах сайта:

| Написание | Вхождений на страницу | Верно? |
|---|---|---|
| `repetati` | 5 | нет, нужно `repetați` |
| `repetați` | **0** | правильной формы на сайте нет нигде |
| `pacientii` | 4 | нет, нужно `pacienților` |
| `pacienții` | 3–13 | да, соседствует с неверным вариантом |

Внутри одного словосочетания `pacienții repetati` первое слово набрано с диакритикой, второе — без. Это не разовая опечатка, а системный дефект шаблона.

Английские соответствия тех же элементов — обрывочный машинный перевод: «Cabinet office» (в английском это правительственный кабинет министров, а не личный кабинет пациента), «Online registration second», «Online registration first time». Заменить на «Patient portal», «Online booking — returning patients», «Online booking — new patients».

Отдельный вопрос к носителю языка: «pacienți repetați» выглядит калькой с русского «повторные пациенты». Румынский узус — скорее «pacienți în control» или «pacienți reveniți»; решение за редактором, но текущая формулировка как минимум требует проверки.

Попутно: четыре из пяти таких «ссылок» — это `<a href="#">` с модальным окном. Для поиска они не ссылки, и анкорный текст самого конверсионного элемента сайта пропадает впустую.

Для проверки использовать `C:\Users\colec\.claude\tools\Scan-Invisible.ps1`.

### D4. Заголовки кеширования

Статика отдаётся с `Cache-Control: max-age=2592000, public` — корректно. HTML отдаётся с `no-cache, private` — для страниц с формами оправданно, но для статей и страниц услуг стоит включить короткий публичный кеш или ESI, чтобы снизить TTFB под нагрузкой. Текущий TTFB 164 мс — узким местом сервер не является, задача низкоприоритетная.
