**Что сломано.** `https://www.mikof.md/` отдаёт `200 OK` без редиректа. Более того, canonical на www-версии указывает сам на себя:

```html
<!-- то, что сейчас отдаёт https://www.mikof.md/ -->
<link rel="canonical" href="https://www.mikof.md">
<link rel="alternate" hreflang="ru" href="https://www.mikof.md/ru">
```

Google уже проиндексировал именно www-копию — в выдаче присутствуют `www.mikof.md/en`, `www.mikof.md/en/contact.shtml`, `www.mikof.md/en/service/35`. Весь сайт существует в двух полных копиях, ссылочный вес и поведенческие факторы делятся между ними.

**Что сделать.**

1. В nginx — 301 с www на голый домен и с http на https:

```nginx
server {
    listen 80;
    listen 443 ssl http2;
    server_name www.mikof.md;
    return 301 https://mikof.md$request_uri;
}

server {
    listen 80;
    server_name mikof.md;
    return 301 https://mikof.md$request_uri;
}
```

2. В Laravel зафиксировать `APP_URL=https://mikof.md` и строить canonical/hreflang/og:url **только** от него, а не от `request()->getSchemeAndHttpHost()`. Сейчас canonical явно наследует хост запроса — отсюда `https://www.mikof.md` в разметке.

3. Canonical должен быть абсолютным, с учётом языкового префикса текущей страницы и **со слэшем или без — единообразно**. Сейчас canonical главной `https://mikof.md` (без слэша), а сама страница доступна и как `/`, и как ``.

**Как проверить.**

```bash
curl -sI https://www.mikof.md/ | head -3          # ожидается: HTTP/1.1 301, Location: https://mikof.md/
curl -sI https://www.mikof.md/ru/service/35 | head -3
curl -s https://mikof.md/ru | grep -o '<link rel="canonical"[^>]*>'   # ожидается: href="https://mikof.md/ru"
```
